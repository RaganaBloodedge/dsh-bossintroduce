# 02 · 自我介绍文案与护栏

> 文档与代码冲突时**以 `scripts/guard.py` 为准**。本文档是它的口径说明与写法细则。

---

## 一、铁律（逐条都必须满足）

1. **默认零数字** —— 提速倍数、测试条数、百分比、吞吐量、方法数、毫秒数一律不写；
   只保留必要的时间/身份信息（例："2026 年 7 月毕业"）。院校背书类数字可例外。
2. **第一句就命中岗位** —— 匹配点不许埋在中段。
3. **120–160 字，≤4 句** —— 超长即判失败重写。
4. **只挑一条最相关、最稀缺的事实当主攻** —— 这是"不同的自我介绍"的实现方式：
   **主攻事实不同，不是换措辞**。
5. **点名 JD 头号要求的原词**，再落自己的对位事实 —— 抽取只选一条；对不上就跳过这个岗位。
6. **未上简历的项目要用也可以**，但必须额外给**链接 + 一句简略介绍**（没有公开链接的私有仓库不可用）。
7. **事实只准来自能力图谱**；**写完必须过护栏校验器**。

**筛选要敢说不**：头号要求没有事实能回应 → 直接跳过。无效打招呼换来的是 HR 反感与账号限流，比少投更贵。

---

## 二、「不同的自我介绍」怎么实现

**同一个用户，面对不同 JD，主攻事实不同 —— 不是换措辞。**

例：一条 JD 的头号要求是「AI 模型权重分发」，主攻就押"从零写推理引擎、自写权重容器解析、直读量化权重"；
换一条 JD 头号要求是「多 Agent 编排」，主攻就改成"双 Agent 编排 + 把护栏做进工具体"。

**选主攻事实的步骤**：

1. 从能力图谱（数据目录下的 `capability-graph.json`）里按 `jd_hits` 找**能回应 JD 头号要求**的条目。
2. 在能回应的条目里，挑**最稀缺、最贴**的那一条（不是最"厉害"的那一条）。
3. 用 `--focus <id>` 声明它，护栏会验证它**真的落在文里**。
4. 若某条目的 `visibility == private` ⇒ **不可用**（护栏直接拒）。

---

## 三、长度档位（`--budget`）

| budget | 铁律目标 | 闸门（判 FAIL 的线） | 句数上限 | 何时用 |
|---|---|---|---|---|
| `resume` | 120–160 字 | 120–200 字 | ≤4 句 | 默认。只引用简历上的事实 |
| `extra` | 150–210 字 | 150–210 字 | ≤5 句 | 引用了 `on_resume: false` 的项目时 |

> 字数口径是**可见字符数**（去掉空白后的全部字符，含英文与技术词、主页链接）。
> 落在闸门内但超出铁律目标区间 ⇒ 打 `WARN`（按铁律 3 应重写压缩），不算 FAIL。
>
> ⚠️ **这两档的边界属于「个人口径」**，可由图谱 `writing_rules.budget` 覆盖：
> `min_chars`/`max_chars` 定义**闸门**（硬失败线），`target_chars` 定义铁律目标区间，`max_sentences` 是句数上限。
> 上表是引擎默认值（不写就按它跑）。

> ⚠️ `extra` 档（150–210）是**由铁律 3 推导**出来的，因为引入未上简历项目要多给「链接 + 一句介绍」，
> 必然超 160 字。**幅度待用户拍板。**

## 四、护栏八项检查（实现口径）

`python scripts/guard.py --file draft.txt --require "<点名词>" --focus <id>`

| 检查 | 通过条件 | 实现要点 |
|---|---|---|
| **长度闸门** | 可见字符数落在 `gate` 区间 且 句数 ≤ 上限 | 句子按 `。！？!?…` 与换行切分 |
| **禁用数字** | 无「无出处数字」 | 先**掩掉白名单上下文**再扫数字。白名单 = 通用基表（日期 / 年月 / 版本号 / 分数线 CET-6·985·211 / 指令集硬件 AVX2·SSE4.2 / 裸年份）+ **本人的技术栈**（图谱 `writing_rules.number_whitelist`，如 `C++20`·`Qt6`·`Gemma 2`） |
| **事实来源** | 文里至少有一个实体能在图谱里找到 | 实体别名 = 项目 name+link+focus_aliases、经历的 org+role+focus_aliases、学校名 |
| **点名词** | 每个 `--require` 原词都出现 | 大小写无关 |
| **主攻事实** | `--focus` 的 id 存在、非 private、且其别名落在文里 | 缺 `--focus` 直接 FAIL（铁律 4 必须声明） |
| **未上简历项** | 每个 `--offresume` 都带**自己的**链接 | `on_resume: true` 的反而报错（不需要 `--offresume`） |
| **黑名单** | 未触犯任何被禁字面项 | 查全局黑名单 + **文中确实出现**的条目的黑名单 |
| **可验证入口** | 文里带 GitHub 主页 | 落实 `writing_rules.must_include` |

### 数字白名单的三条硬规矩（都是踩过的坑）

1. **顺序即正确性**：**带年份的长模式必须排在裸年份前面**。
   否则「年份」先掩掉 `2026`，`2026 年 7 月` 就再也匹配不上，`7` 会被误杀。
2. **必须掩「上下文」而不是只掩数字**：`Gemma 2` 被放行的是整体，只掩 `2` 会永远掩不中。
   掩码用**等长空格**，保证后续上下文切片位置不乱。

**版本号必须「长得像版本」**：带 `v` 前缀，或至少两个点（`3.13.1`）。
早期写成 `\d+(\.\d+)+` 时，`提速 5.3 倍` 里的 `5.3` 被当成版本号放行 —— 业绩数字成功冒充。
**单位型数字（`5.3 倍`）一律不放行。**

3. **技术栈要按人配置**：`Gemma 2`、`Qwen3` 这类只对某个人有意义，**不写在引擎里** ——
   由图谱 `writing_rules.number_whitelist` 提供（每项 `{"label": 说明, "pattern": 正则}`）。
   图谱没写才退回引擎内置的通用兜底（`C++20` / `Qt6` / `Python 3.13` 这类常见写法）。
   正则写错会**报用法错退出码 2**，不静默跳过 —— 白名单写错等于没有护栏。

### 放行某个数字

```bash
python scripts/guard.py --text "…" --require "<JD 头号要求的原词>" --focus <主攻事实 id> \
  --allow-number "16" --why "JD 原文写明的薪资结构，属岗位信息非业绩数字"
```

`--allow-number` 与 `--why` 必须**成对且数量一致**，否则用法错（退出码 2）—— 放行要留理由。

## 五、黑名单怎么抽「被禁字面项」

规则：**引号前面 10 字内出现否定词**（不得 / 不要 / 不能 / 禁止 / 严禁 / 不写 / 勿写 / 别写）才判为禁止。

- `写「从零实现」，**不写「自研引擎」**` ⇒ 禁「自研引擎」，「从零实现」是**允许项**，不会误杀。
- `**不得写「完全独立完成」「独立开发」**` ⇒ 连续引号共享同一个否定前缀，两个都被禁。

**写黑名单时把「允许怎么写」和「禁止怎么写」成对写在一句里，用引号标出被禁的字面词** ——
否则护栏抽不出被禁项，等于没有这道检查。

## 六、退出码

| 码 | 含义 |
|---|---|
| 0 | 全绿，可以交给 `say` 发出（**这是发出前的最后一道闸，过了就直接发**） |
| 1 | 有 FAIL，改写后重跑，**不要带病发出** |
| 2 | 用法 / 环境错误（缺图谱、`--allow-number` 没配 `--why` 等） |

> 🔴 自从发送改由执行器代点（`say`），护栏的地位从"建议"变成"闸门"：
> 文案一旦发出不可撤回，**退出码 1 还去 `say` 等于把不合格的话术直接发给 HR**。
> 拿不准就先用 `fill <文案>` 只填不发，看一眼界面上读起来对不对，再决定要不要 `say`。
